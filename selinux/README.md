
## 1. Enforcement Modes
*Always check what mode SELinux is in before troubleshooting.*
* **Verify current mode:** `getenforce`
* **Change (Temporary):** `setenforce [MODE]`
    * `0`: **P**ermissive (logs violations, does not block - good for debugging).
    * `1`: **E**nforcing (blocks and logs violations).
* **Change (Persistent):** `vim /etc/selinux/config`
    * Change line to `SELINUX=enforcing` or `SELINUX=permissive`.
    * *Note: Requires `systemctl reboot` to apply correctly.*

## 2. Managing File Contexts
*Every file/process has a label. Services (like Apache) can only read files with specific labels (e.g., `httpd_sys_content_t`).*
* **Verify contexts:** `ls -ldZ /var/www/html`
    * `-Z`: Displays the SELinux security **c**ontext (look for the part ending in `_t`).
* **Define Rule:** `semanage fcontext -a -t httpd_sys_content_t '/custom(/.*)?'`
    * `-a`: **A**dd a new rule.
    * `-t`: Define the **t**ype (label).
    * `(/.*)?`: Regex meaning "this directory and everything inside it".
* **Apply Contexts:** `restorecon -Rv /custom`
    * `-R`: **R**ecursive.
    * `-v`: **V**erbose (shows relabeling process).

> **Crucial info:** `semanage` ONLY saves the rule in the policy database. It does not touch the files! You MUST run `restorecon` to actually apply the labels to the disk.

## 3. SELinux Booleans
*Built-in ON/OFF switches for common scenarios (like letting Apache read user home directories).*

* **Search:** `getsebool -a | grep home`
    * `-a`: Lists **a**ll Booleans.
* **Modify:** `setsebool -P httpd_enable_homedirs on`
    * `-P`: **P**ersistent (saves across reboots). If you forget `-P`, the rule dies on restart!
* **Pro tip:** Use `man -k _selinux` to find man pages with useful info about specific SELinux Booleans.

## 4. Troubleshooting (When stuff doesn't work)
*Instead of disabling SELinux, just read the logs.*

* **Search Audit Log:** `ausearch -m AVC -ts today`
    * `-m`: Filter by **m**essage type (`AVC` = Access Vector Cache, basically an SELinux denial).
    * `-ts`: Filter by **t**ime **s**tart (e.g., today).
* **Check system logs:** `less /var/log/messages`
    * Search for the word `sealert` to find the exact alert generated by `setroubleshoot`.
* **Analyze Issue:** `sealert -l 9a96294a-239b-4568-8f1e-9f35b5fb472b`
    * `-l`: **L**ookup the UUID from the log.
    * *Why it's awesome:* It gives a human-readable explanation of what was blocked and literally provides the exact `semanage`/`restorecon` copy-paste commands to fix the policy.
